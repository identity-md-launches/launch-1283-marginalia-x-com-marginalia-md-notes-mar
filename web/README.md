# Marginalia site

A static, wallet-connected front end for the live launch #1283 contracts on Ethereum mainnet. It reads the
chain directly through public RPC nodes and signs with the visitor's browser wallet. No backend, no analytics,
no third-party script. The export lives in `../dist/` and works from any static host or IPFS gateway subpath
(relative base, hash routing).

## Pages

| Route | What it shows | Transactions |
| --- | --- | --- |
| `#/` | Feed of notes and theses from `NotePosted`, live status from `noteOf`, outcome and settle price from `Settled`; filters by token, author and kind | – |
| `#/author/<addr>` | `records(address)` (score, posted, right, wrong, broken, retracted, judged wins) and the author's notes | – |
| `#/note/<id>` | Observations (`Observed`), horizon end, 6 h settlement window, outcome, parent/child links; keeper buttons; author claims | `observe`, `settle`, `settleThesis`, `claimDeposit`, `claimRefund` |
| `#/post` | Call or thesis; venue finder; checkpoint with 1 h to 6 h countdown; cost breakdown; approval to the router for exactly stamp + MARG_BUY + bond; post | `router.checkpointVenue`, IMD `approve(router, imdIn)`, `router.note` |
| `#/seal` | Client-side `sealHash`, checkpoint state, author seal events, the 30 min to 6 h window, and existing reveal drafts. **New sealing is disabled** under the router-only approval policy. | Existing reveals open Post; no hook approval or new seal transaction |
| `#/pools` | Current pools, selectable older day/week epochs, judging/sweep eligibility and connected author claims | `hook.sweep`, `claimDeposit`, `claimRefund` |
| `#/about` | How it works, every contract address with explorer link | – |

## Configuration

Everything an operator might change is in two places:

- `dist/imd-deployment.json` (generated by `scripts/manifest.mjs` from the deployment handoff and
  `network.json`): chain id, contract addresses, ABI paths and hashes, the `network` block with the public RPC
  URLs, explorer and Uniswap v4 addresses, and `walletAddChain`. The app fetches this file at runtime
  (`src/config.ts`, `loadDeployment`) and reads router, judge and treasury from `hook.router()` etc.
- `src/config.ts`: the deployment block, bounded log-tail/overlap/chunk sizes, the canonical Uniswap v3/v2
  factory and WETH addresses the venue finder uses (cross-checked against the router's own constants at
  runtime), and the two canonical links.

ABIs: `public/abi/*.json` are the full ABIs from `forge build` in canonical JSON (sorted keys); `src/abi.ts`
holds typed subsets of the same entries. The committed full exports and typed subsets are checked by `tests/live-read.ts`; rebuilding the frontend does not rebuild or change contracts.
No WalletConnect project id is used; the site talks to injected (EIP-1193) wallets only.

## Build

```sh
cd web
npm ci                      # installs from package-lock.json
npm run typecheck           # tsc --noEmit
npm run build               # tsc + vite build  → ../dist
node scripts/manifest.mjs   # writes ../dist/imd-deployment.json (needs ../.imd/reads/deployment.json and network.json,
                            # or pass both paths as arguments)
node scripts/check.mjs      # verifies the manifest, hashes, ABI binding and static-hosting rules
npm run preview             # serves ../dist locally
```

Re-run `manifest.mjs` after any change to `dist/`; the asset hashes must match the final bytes.

## History and sealing limits

The feed reads recent events first, then backfills from deployment block **26169583**. Each refresh makes
at most four recent and four historical log queries, each covering at most 2,000 blocks (approved RPC
fallback/retries may add transport attempts). It persists successful ranges, events, the recent cursor and
an independent historical cursor after each request. Historical batches skip successful ranges, advance
past refusals, and cycle back to retry missing ranges. Existing browser caches migrate without discarding
their logs. A 64-block overlap and block-hash anchor are retained; `noteOf` is always refreshed on chain.

The count beside the ledger says **History incomplete** until coverage is complete. Expand that row to see
the read block, coverage explanation and any refused block ranges, then use **Load more history** to advance
another batch. **Refresh** and page reloads also continue the saved scan. The same coverage control appears
on other pages while history is incomplete. Public nodes can still refuse historical data: author records'
note lists, evidence, seals and claims cover the events successfully read so far, without claiming unavailable
history is empty. Clearing browser storage resets history and removes saved seal drafts. No backend, archive
API or additional RPC endpoint was added.

New sealing is disabled because the immutable hook pulls its stamp itself, requiring a hook allowance that
the site's router-only approval policy forbids. Its checkpoint status and hash preview remain readable.
Existing seals may be revealed from saved parameters or the Post form: the app checks the connected author's
live seal, subject, hash and reveal window independently of ordinary checkpoint age. Explicit reveals never
silently fall back to ordinary posting; their router deadline is capped at seal expiry.

All posting approvals authorize only the router for the exact, fully displayed IMD total. Targets support
hundredths of one percent, and IMD bonds support up to 18 decimals. Raw observation accumulators are labeled
as raw integers; token balances use the token's own decimals or an explicit fallback.

Publish **only `dist/`**. The unrelated `helper/` in the repository is not part of this app or its asset inventory.
The share card is bundled at `share-card.png`; without a supplied hosted origin, OG/Twitter image paths are
relative. Verify absolute social preview URLs and actual platform unfurls once the final origin is known.

## Validation

See `VALIDATION.md` for reproduction evidence, the Better Interface review and untested live behavior.
No real transaction is needed for these tests. With frontend dependencies installed, from `web/`:

```sh
npx --no-install esbuild tests/revision-unit.ts --bundle --platform=node --format=esm --outfile=../test/scratch/revision-unit.mjs
node ../test/scratch/revision-unit.mjs
npx --no-install esbuild tests/history-unit.ts --bundle --platform=node --format=esm --outfile=../test/scratch/history-unit.mjs
node ../test/scratch/history-unit.mjs

# Independent browser tooling; does not change this project's dependency manifest or lockfile.
npm install --prefix /tmp/marginalia-browser playwright@1.64.0 --cache /tmp/marginalia-npm-cache
PLAYWRIGHT_BROWSERS_PATH=/tmp/marginalia-browsers /tmp/marginalia-browser/node_modules/.bin/playwright install chromium
PLAYWRIGHT_BROWSERS_PATH=/tmp/marginalia-browsers PLAYWRIGHT_MODULE=/tmp/marginalia-browser/node_modules/playwright/index.mjs EVIDENCE_DIR=../test/scratch/browser-evidence node tests/revision-browser.mjs
```

For the new history cases, run the same browser command with `HISTORY_ONLY=1`; add `BROWSER=webkit` to
use an installed WebKit. `HISTORY_BEFORE=1 HISTORY_ONLY=1 SITE_DIR=/path/to/previous/dist` reproduces the
three reopened defects on the prior accepted export. Dependencies can be installed in an isolated copy of
`web/` under `/tmp` to leave repository manifests, lockfiles and dependency paths unchanged.

The browser runner owns and closes its local static preview under `/preview/`, blocks outside requests, and
mocks both RPC and the wallet. `MODE=before SITE_DIR=/path/to/original/dist` reproduces the reported defects
against an original export; the normal mode asserts their corrected behavior. Its dates and accounts are
fixtures, not deployment settings. `tests/live-read.ts` is a separate read-only check: bundle it like the unit
test and pass a permitted RPC URL and the absolute `dist/imd-deployment.json` path. It never submits a transaction.

The optional `scripts/share-card.mjs` renders the bundled typographic artwork using the same isolated
Playwright module and local fonts. Rebuild and regenerate the asset manifest after changing the artwork.
