# Marginalia site

A static, wallet-connected front end for the live launch #1283 contracts on Ethereum mainnet. It reads the
chain directly through public RPC nodes and signs with the visitor's browser wallet. No backend, no analytics,
no third-party script. The export lives in `../dist/` and works from any static host or IPFS gateway subpath
(relative base, hash routing).

## Pages

| Route | What it shows | Transactions |
| --- | --- | --- |
| `#/` | Feed of notes and theses from `NotePosted`, live status from `noteOf`, outcome and settle price from `Settled`; filters by token, author and kind | – |
| `#/author/<addr>` | `records(address)` (score, posted, right, wrong, broken, retracted, judged wins) and the author's notes | – |
| `#/note/<id>` | Observations (`Observed`), horizon end, 6 h settlement window, outcome, parent/child links; keeper buttons; author claims | `observe`, `settle`, `settleThesis`, `claimDeposit`, `claimRefund` |
| `#/post` | Call or thesis; venue finder; checkpoint with 1 h to 6 h countdown; cost breakdown; approval to the router for exactly stamp + MARG_BUY + bond; post | `router.checkpointVenue`, IMD `approve(router, imdIn)`, `router.note` |
| `#/seal` | Client-side `sealHash`, seal, the 30 min to 6 h reveal window, the author's seals, reveal by prefilling the post form | IMD `approve(hook, STAMP)`, `hook.seal` |
| `#/pools` | `refundPool(day)`, `thesisPool(week)`, judging state from the judge, sweep | `hook.sweep` |
| `#/about` | How it works, every contract address with explorer link | – |

## Configuration

Everything an operator might change is in two places:

- `dist/imd-deployment.json` (generated by `scripts/manifest.mjs` from the deployment handoff and
  `network.json`): chain id, contract addresses, ABI paths and hashes, the `network` block with the public RPC
  URLs, explorer and Uniswap v4 addresses, and `walletAddChain`. The app fetches this file at runtime
  (`src/config.ts`, `loadDeployment`) and reads router, judge and treasury from `hook.router()` etc.
- `src/config.ts`: the deploy block logs are scanned from, the log chunk size, the canonical Uniswap v3/v2
  factory and WETH addresses the venue finder uses (cross-checked against the router's own constants at
  runtime), and the two canonical links.

ABIs: `public/abi/*.json` are the full ABIs from `forge build` in canonical JSON (sorted keys); `src/abi.ts`
holds typed subsets of the same entries. Both are generated by `test/scratch/genabi.mjs` from `out/`.
No WalletConnect project id is used; the site talks to injected (EIP-1193) wallets only.

## Build

```sh
cd web
npm ci                      # installs from package-lock.json
npm run typecheck           # tsc --noEmit
npm run build               # tsc + vite build  → ../dist
node scripts/manifest.mjs   # writes ../dist/imd-deployment.json (needs ../.imd/reads/deployment.json and network.json,
                            # or pass both paths as arguments)
node scripts/check.mjs      # verifies the manifest, hashes, ABI binding and static-hosting rules
npm run preview             # serves ../dist locally
```

Re-run `manifest.mjs` after any change to `dist/`; the asset hashes must match the final bytes.
